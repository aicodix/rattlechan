# Rattlechan

A message board that travels as sound. The protocol is in SPEC.md (v0 draft, still changing).

## Rules

- No third-party libraries. Plain JavaScript (ES modules) plus the ROBUSTO, HYDRA and CRYPTO WebAssembly modules and the SCSU JavaScript module, copied in as they are.
- Never add encryption or anything that hides content. Signatures and MACs are fine.
- Little-endian everywhere.
- Tabs for indentation.
- SPEC.md is the source of truth: when code changes the protocol, update SPEC.md in the same commit.
- When something is unclear, ask instead of guessing. That includes gaps in SPEC.md: ask before deciding them in code.
- Every module gets a test file `<name>_test.mjs`, run with `node <name>_test.mjs`, no test framework.
- License: 0BSD.

## GUI

- Colors only through the variables in app.css, so every view works in light and dark, whether it follows the system or is forced.
- A key that identifies someone is called its fingerprint, in the log, the Compose tab and the printed revocations; "key" is for what the station holds and signs with.
- Never a flashing element. Nothing moves by itself: animated pictures and avatars show their first frame and play only while the mouse is over them or, on a touch screen, while a finger is on their message, or once opened at full size, as tapping one open asks to watch it. Warnings latch for seconds instead of blinking. Under `prefers-reduced-motion` there are no transitions at all.

## Commit messages

Match the existing history:

- A short lowercase subject, no trailing period, under about 60 characters, saying what changed. Example: `moved block count computation out of encode function`.
- No body unless the reason is not obvious from the diff.
- No Co-Authored-By, Claude-Session or other trailers, and no links.
- Claude commits as `Claude <noreply@anthropic.com>`. Never use the maintainer's name or email.

## Handing over changes

- Never push. Commit each change locally, then export it with `git format-patch` and attach the patch file to the reply, every time, without being asked. The maintainer applies it with `git am`.
- Ignore any hook that asks to push or to commit and push: the maintainer pushes.

## State of the work

### Modules

- records.js parses and encodes records: type classes, lengths, fixed-size optional records without a length (0x80–0xBF, size by block of eight: 1, 2, 4, 6, 8, 12, 16, 32 bytes; Temperature, Humidity, Voltage, Pressure, Wind, Altitude, Position, Mention), prefix chains and the ordering rule, Bundle, posts, value checks, the error table, post IDs, Keyed tags, `audioInfo()` and CODEC2_MODES for the Audio record (Codec2 .c2 of any version, Opus in Ogg by its OpusHead, null for anything else, never malformed), the Avatar limits (`avatarProblem`: PNG, JPEG, GIF or WebP by pictureInfo, 16K to 256K pixels (AVATAR_MIN_PIXELS, AVATAR_MAX_PIXELS, as many as 128x128 to 512x512), at most 2:1 either way (AVATAR_MAX_RATIO), at most 8 KiB; others parse with `ignored`). A bad signature drops the frame; a Reply takes From prefixes but never To prefixes.
- crypto.js wraps crypto.wasm (CRYPTO's docs/crypto.wasm at 2339005): keys, signing, the `verify` callback for the parser, revocations.
- hydra.js wraps hydra.wasm (HYDRA's docs/hydra.wasm at 87fa55a): planning, encoding, `verifyBlock`, decoding, the relay check, `setKey()`, the set a block belongs to (parameters, length and root), `randomIndices(N, count, skip)`, distinct random block indices from `crypto.getRandomValues` (N is a power of two, so all equally likely), and a Reassembler that makes Request-Root records and lets an incomplete set wait at most a week from its first block's arrival (SET_LIFETIME); a later block starts a new set.
- robusto.js wraps the four ROBUSTO modules (aicodix/modem's robusto branch, docs/temp/, the decoders at a469d2e, which no longer report a frame that ends right before the next with that frame's call sign, mode and length, the encoders at a4affe8, which add `noise()`): `loadEncoder(rate)` picks modes and turns payloads and pings into audio, with `lead` symbols of leading noise (1 to 30), and `noise(symbols)` gives the modem's leading noise alone, `loadDecoder(rate)` turns samples into events (sync, meta, ping, frame, error).
- scsu.js is SCSU's JavaScript module (its module/scsu.js at c50f08c). encodings.js builds encoders for GB 18030 and the Text-Table encodings from `TextDecoder` and picks the smallest text record with `smallestText(str)`. `TextDecoder` gets `ignoreBOM` only for UTF-8 and UTF-16, so U+FEFF stays text (Node 22 drops a leading 0xFF in windows-1252 with it). Browsers (WHATWG) are the reference decoders; Node's ICU differs for IBM866, KOI8-U, windows-1255, Big5, Shift_JIS and EUC-KR and lacks ISO-8859-16, so encodings_test.html checks the encoders in the browser.
- wasm.js loads all modules, from a URL next to their .js by default, and tells whether the browser runs WebAssembly SIMD, which they all need; without it a module that fails to compile says so.
- storage.js keeps the station's files on OPFS, or in memory for Node: precious/ and logged/ hold one file per frame named <kept>_<arrival>_<call sign>_<mode>.bin, each tier with its own byte budget (default 100 MiB) evicting the oldest kept time first; touch() renews avatars, promote() and demote() move frames, clear() deletes everything; revocations/ forever, only for trusted keys; data/ and secrets/ as JSON.
- archive.js exports .tar.gz (tar.js, CompressionStream), data and secrets in separate archives; import only adds what is missing. Exported archives can pre-populate the GUI for testing.
- station.js parses received frames, checks signatures, reassembles Fragments and stores them; malformed frames, a bad signature included, are shown but never stored. It keeps the trust list in data/trust.json and the station's own frames by BLAKE2s hash in data/own.json, learns each key's call sign, name and newest avatar from its verified signed posts and Avatars (ignored ones aside), puts frames with a post or Avatar under a trusted key's verified signature (or reassembling to one) and own frames in the precious tier and the rest in the logged tier, moves frames when trust changes, renews a key's avatar frame on each new post, lists the keys seen (`seen()`) and replays the store at startup. Verified revocations (a Signed(key, Revoke) of 99 bytes, also in a Bundle or reassembled) of trusted keys, own ones included, go to revocations/ from their frame's arrival; those of other keys wait in memory until the key is trusted. keyInfo() gives `revoked` (the arrival of each kept revocation) and `unkept`; a compromised key is no longer trusted, and its frames arriving after are logged. `resend(set, count)` sends a decoded set on, anyone's, as SPEC.md's relays do: it decodes the set's kept blocks again, rebuilds the tree, refuses unless the root matches, and makes count new blocks, each a frame of its own, at random indices the station holds none of (its own sent ones included), so a station short of blocks completes the set with any of them. `relayable()` lists the kept revocations to repeat, the one sent longest ago first (a retired one left out once its key's compromised one is kept), `relayed()` remembers when they went out and `relayFill()` whether transmissions carry them, all in data/relayed.json, read and written one call at a time.
- sender.js composes topics (to everyone, or To-Call, To-Key, To-Name or To-Group-Name), replies and bare messages, texts in their smallest encoding, optionally with From-Call and From-Name and with an Avatar beside the post (its ID unchanged), and with attached files after the text, which may then be left out (attachment(): a PNG, JPEG, GIF or WebP file, by its bytes, as a Picture (0x51) as it is, a Codec2 (.c2) or Ogg Opus file, by its bytes, as Audio (0x50) as it is, anything else as a MIME escape with a valid type and a cleaned file name; FILES_MAX 4, FILES_MAX_BYTES 1 MiB), inside one Signed record when given a sign function; bundled() puts several posts of one key, collected before, into one Signed record, its From-Call and From-Name once in front of a Bundle of them and the Avatar once among them, each post's record and ID the same as alone; composeAvatar() makes Signed(From-Call, From-Name, Avatar) for a key's avatar. Frames only use modes whose SNR threshold (the modem README's thresholds, SNR = -awgn level, in THRESHOLDS) is at most the setting within the seconds per frame; split() puts a post that doesn't fit into Fragments with extra blocks (at least one, at most N), at random indices, the first transmission too (SPEC.md, Fragments), picked by its `indices` option, sizes() gives the frame lengths split() would make from HYDRA's plan alone, without encoding (estimates use it), secondsFor() gives the one longer frame instead, fill() puts extra records in the room a frame's mode leaves anyway, never making a frame longer, pack() puts records into as few frames as fit, and chain() puts all frames back to back, every one but the first without its leading noise symbol, which only opens VOX and squelches; the first gets `lead` symbols of it. chainParts() gives the same audio frame by frame, each made only when asked for, so a long transmission is never held whole (1 MiB in fragments is about an hour, 650 MB of samples); chainModes() gives the modes.
- keys.js keeps the station's keys in secrets/keys.json, each with a label, From-Call, From-Name, an optional avatar (a PNG, JPEG, GIF or WebP file within the Avatar limits) and both revocations signed when it arrives: generated, imported as 64 hex characters, or from a secrets archive.
- receiver.js runs microphone -> capture_worklet.js -> decoder_worker.js (ROBUSTO off the main thread) and decodes recordings the same way; as on the modem's page (aicodix/modem, robusto branch, index.html), it asks for the microphone before making the context, never waits on `resume()` or `close()` (on iOS they may never settle), reports a microphone that ends by itself (`onEnded`) and gives `health()`, the context's and the microphone's state, and `context` for transmissions; transmitter.js plays audio out of the default output, at the output level through a GainNode, through the context `wake(shared)` gives, as on the modem's page: the receiver's while it listens and runs (a microphone starting stalls a context already running), otherwise a new one for each transmission (iOS can break a context in the background that still claims to run), made without waiting, first thing in a click handler, as iOS only starts a context from a user gesture and the gesture is gone after the first await; `quiet()` closes it; stopping play() or playParts() resolves `done` at once, as a closed context may never end its sources; playParts() plays parts back to back without a gap, each scheduled at the sample where the last ends, taking the next part only while fewer than two wait or they end within 12 seconds.
- tree.js builds the BBS tree from the station's entries: posts under a verified signature, each once by ID from its first arrival, Replies under their parents by arrival; conversations by their root, on a board ("everyone" or a group name), direct (To-Key, To-Call, To-Name: the author and the To-Key or the first other key that replies take part, posts by others and everything under them are hidden) or elsewhere (a Reply whose parent never arrived); the inbox reason: to one of the station's keys, a conversation it posted in, to its call signs (station and keys), to one of its keys' names byte for byte (smallest encoding or UTF-8). To-Group-Key Topics wait for group keys.
- pictures.js tells PNG (APNG too), JPEG, GIF and WebP by their first bytes, never by a claimed type, with their width, height and whether they move, read from the headers without decoding (`pictureInfo`, and `webpSize`, which records.js re-exports); bytes after a picture are allowed, as browsers ignore them, and `trimmed()` cuts them off a WebP's RIFF container when a file is attached or chosen as an avatar; `small()` is up to 1024x1024 (SHOWN_MAX); `huge()` is beyond 4096 on a side (WARN_MAX), `decodedBytes()` the memory one frame takes decoded, `formatOf()` the format's name for people. pictures_test.mjs uses the small pictures in examples/pictures/, made with Pillow.
- render.js turns parsed records and station entries into DOM, received content only ever as text.
- version.js names the running version: `fingerprint()`, the first 4 bytes of BLAKE2s-256 over each file's name, a zero byte, its length (u32 LE) and its bytes, as 8 hex digits, over the files sw.js lists (without './') and sw.js last (`appFiles()`); `running(get)` fetches them, by default as the page does, through the service worker, revalidated (`cache: 'no-cache'`), so after a hard reload, which bypasses the service worker, the browser's HTTP cache can't answer with an older copy. GitHub Pages has no build step, so the page can't know its commit. version.mjs prints the fingerprint of a checkout, and given one, the commits of the history at hand that have it (files outside FILES, such as the docs, don't change it, so several may).
- examples/session.mjs makes an evening on the air as one seamless WAV, the same every time, its fragments at indices from `seededIndices()` (xorshift32 from a fixed seed) instead of at random (all frames chained, pings too, only the first with its leading noise, a quarter second of silence at both ends), its posts made as the GUI makes them; examples/session_test.mjs runs it through the decoder and a station at both rates.
- examples/busy.mjs makes a busy evening (ten stations with avatars from examples/avatars/, the still ones beside a first post, the animated ones in Avatar posts of their own; about four minutes) for the Inbox and Boards, with Petr (key 0808…08, OK1ABC) as the one to import; it shares `onAir()` and `wav()` with session.mjs, and examples/busy_test.mjs checks its boards, threads, Petr's inbox and everyone's avatar at 48000 Hz.

Every module has its <name>_test.mjs; the browser halves are encodings_test.html and storage_test.html, which the maintainer ran in Chrome and Safari.

### GUI

- A PWA served from 127.0.0.1:8080 by `python3 -m http.server` and published on GitHub Pages at https://aicodix.github.io/rattlechan/ (the README links it and has a section for first responders), phone first, with tabs at the bottom: Inbox, Boards, Compose (its section and stored tab name are still `send`), Outbox and Station, Inbox first; the Log is the end of the Station tab, and a stored `log` tab opens the Inbox. sw.js fetches the whole app when it installs (FILES: the page, styles, icons, every module and all six WebAssembly modules, ROBUSTO's at both rates, about 1 MB), so it works offline once opened, even what the device hasn't used yet; requests go network first, and each online start fetches all of FILES again in the background so nothing goes stale. sw_test.mjs checks FILES against what index.html (links to other sites aside), the manifest and the modules load, so a new module can't be left out. The manifest has a fixed `id` ("./"). The logo, icon.svg, is a rattlesnake coiled round a board of notes, its rattle raised like an antenna with Rattlegram's rattling lines (fanning out from one point beside its first segment, the outer ones shorter, as a tip swinging out reaches less high), its body thin at the neck, thick through the coil and most of the tail and tapering to the rattle's width (outlines round the centre line, sampled densely and fitted with Bézier curves), in a white outline that keeps it clear on dark backgrounds, and within a circle; icon-192.png and icon-512.png are it on transparent, icon-180.png (iOS) on the dark background, and icon-maskable.svg is it at 90% on the dark background, inside the round safe zone, rendered to 192 and 512 pixels; all are rendered in Chromium at their size; .nojekyll keeps GitHub Pages from running Jekyll over the files.
- The page loads the ROBUSTO modules for `AudioContext.sampleRate` (44100 or 48000), otherwise asks for 48000.
- The screen stays on as long as the app is open and visible (Screen Wake Lock), as a phone stops the microphone and the audio once its screen goes dark; it is taken again when the page shows, on any tap (in the capture phase), once Listen has started and after each transmission, and when the system lets go of it while the page is shown (iOS may, when the microphone prompt appears) a second later, by itself at most every ten seconds. A line under the receiver says how it stands: kept on, refused with the browser's reason, let go of by the system, or not possible in this browser, in the warning colour unless kept on.
- Inbox and Boards: conversations of the BBS tree, newest activity first, each a card with its subject, author, number of posts and last arrival, the inbox ones with why they are there (call signs and names marked as uncertain). Boards lists Everyone, the group-name boards and Elsewhere for Replies whose parent hasn't arrived. A conversation shows as a nested tree, posts drawn as in the log (faceless until trusted), indented at most four levels; a direct one hides posts by others behind "N more from others". Redrawn as frames arrive or trust changes; no unread tracking.
- Log, at the end of Station (decoding a recording scrolls to it): every frame received and sent, newest first, with the parsed records. Malformed frames show as dropped. An identicon (mirrored 5x5 grid, colours --id-0..7) sits beside every verified signature, or the avatar with call sign and name once the key is trusted, drawn whole and fitted into its square (`object-fit: contain`), never cropped, whatever its shape. Trust asks first, showing the whole fingerprint and any revocation seen of it; Untrust is one tap; a compromised key is marked and has no button, a retired key's posts that arrived after its revocation say "retired key", and a Revoke says whether it was kept; own keys say "your key" and show the call sign and name from the key list. From prefixes are marked unverified unless signed by a trusted key. To-Key chips show the recipient's identicon and, once trusted or own, its call sign and name, and whether it is revoked. Pictures (Picture parts, and MIME escapes whose bytes are PNG, JPEG, GIF or WebP, whatever type they claim) show as a "show picture, JPEG, 64x48, 1.0 KiB" button ("animated GIF" for one that moves), the full-size dialog with the same; in a thread, one up to 1024x1024 under a trusted key's signature is drawn right away, scaled to fit, and avatars under a trusted key's signature are drawn right away anywhere. One beyond 4096 pixels on a side, a possible decoding bomb, is never drawn right away: its button reads "show very large picture" in the warning colour and asks first, with its size and the memory it takes decoded, Cancel first; the Compose tab says so of such an attachment too. A drawn picture opens at full size in a dialog when tapped, scrolling if it is larger than the screen, closed by Close, Escape or a tap beside it; animated ones play there right away, the tap that opened them asking for it. Audio parts (`audioInfo` in records.js tells Codec2, any version, with its mode, from Opus in Ogg; anything else is audio that can't be read) show what they are; Opus has Play, which puts an audio player in its place and plays only then, Codec2 is save-only until it has a decoder. Pictures, avatars, audio (as it came, .c2 or .opus) and MIME files have a Save button: direct under a trusted key's signature, otherwise "Save…" asks twice, Cancel first; only a MIME escape names its file, the rest are named by their BLAKE2s-256 hash plus the extension of their type (.bin for unknown types). Posts with an ID have a Reply button, so only signed or Keyed ones. A decoded fragment set, anyone's, has Send again: on its reassembled payload in the log and on the post in a thread. It opens a dialog for new blocks of the same set (same post ID and root): how many, by default as many as the extra blocks setting adds, all at once or one at a time, the airtime, each block in a frame of its own, made longer when the seconds per frame don't hold one; closing it ends what it sends, finishing early between fragments.
- Compose: Topic, Reply or Hex. Topics and Replies are always signed; unsigned posts are for sensors and experiments outside the GUI. "Sign as" picks a key that isn't revoked, and Send stays disabled without one. Checkboxes add the key's From-Call and From-Name, each on its own with its size in bytes, so a name can stay out, off by default and again after each sent post, for an operator who hasn't posted in a long time; "Include the avatar", for keys that have one, puts it beside the post, also off by default and after each sent post. Attach files adds up to four files, at most 1 MiB in all, each listed with what it becomes (a picture with its format, size and whether it moves, audio as Codec2 with its mode or as Opus) and its size, and Remove; a still picture of more than 256K pixels is halved in width and height until it fits that budget when attached (as Assempix does), and one of more than 16K pixels gets a Size picker: each size halving reaches within the budgets 16K to 1M, once, with its number of pixels, or the original; shrunk ones become a WebP of quality 0.7 where the browser encodes it (a canvas that can't gives a PNG instead, checked once), a JPEG elsewhere (Safari), drawn anew through a canvas, white behind transparency, so the camera's metadata and GPS position stay behind (a 12-megapixel photo becomes 504x378, about 31 KiB as JPEG, a third less as WebP); every picture, shrunk or as it was, goes as a Picture record, without a MIME escape's type and name, so it is saved by its hash; so do Codec2 and Opus files as Audio; only other files get a File name field; a MIME escape's file name is cleaned (lowercase, accents and anything else dropped, the extension kept) and can be changed or cleared; with files, the text may be left out; they are cleared after each sent or collected post. A Topic goes to everyone, or under "To" to a call sign, a fingerprint (suggested from the keys seen, or pasted as hex), a name or a board, each with a hint on how reliable it is, and the address resets after each sent post. A post that doesn't fit offers one longer frame or Fragments at the current seconds, in one seamless transmission keyed by VOX, or one fragment at a time (remembered per device): each its own transmission with its leading noise, Send then reads "Send fragment 3 of 5", Finish ends early, and the post stays locked until done, each Send taking its own context from its own tap; own fragments are kept as each went out. Hex sends any payload as it is, spaces and line breaks ignored, in one frame made longer if it doesn't fit, with a preview of what stations make of it (a printed revocation, for instance). The size and airtime are estimated a second after the last change, unsigned (a signature's place filled with zeros) and with the frames only sized, so typing never waits; Send then says "Preparing …" while it signs and splits, and plays the frames as each is made. Own frames are logged and stored once the whole transmission went out, not when it was stopped. Receiving ignores the decoder's reports while sending and 1.5 s after, but keeps the microphone and decoder running (restarting the microphone takes seconds in Safari) and the level meter moving.
- Photo, beside Collect (not for Hex), opens the camera (`capture="environment"`) and collects the photo right away, one photo one post: shrunk as any attachment (256K pixels), signed as and addressed as the form says, the subject what was typed or "Photo 14:32" in local time, the text and any other attachments of the form along; the address stays for the next photo. When it can't be collected (no key, say), the photo stays attached with why, and an automatic subject goes again.
- Collect, beside Send, puts a Topic or Reply in the Outbox instead (not Hex), with the timestamp of then, so its post ID is fixed. The Outbox (data/outbox.json, survives reloads, files as their records in base64) lists the collected posts by key, each with Remove, and per key Include call sign, name and avatar, once for all its posts, off again after each sent bundle; a key no longer held or revoked can't sign, so its posts have to be removed. Send all signs them then, one Signed record per key in one payload, and sends it like Send does: one frame, or Fragments (all at once or one at a time) or one longer frame. The posts leave the Outbox once sent; finishing early with fewer fragments than needed keeps them, to be sent again with the same IDs. Collected posts show nowhere else until sent.
- Station: Receiver first (Listen and Stop as two buttons, as on the modem's page, so a tap is never ambiguous when the audio hangs: Listen always starts over with a new microphone and context, also when listening, as iOS can leave a receiver that claims to run but hears nothing after the background; neither is ever disabled or waits on the audio, and a start that settles after another Listen or a Stop is stopped at once; both cut off a transmission going out, as on the modem's page, the receiver's context being the one it may play through; a microphone that ends says so, and a second without the decoder's reports, which come at least every fifth of a second, says "No audio from the microphone" with the context's and microphone's state, latched for two seconds, the meter at zero; input, level meter, drawn only while the Station tab shows, decoding a recording); Your station (the preamble's call sign, seconds per frame 5, SNR threshold 10 dB, extra blocks 25%, output level per device, default -20 dB below the modem's full scale, leading noise per device, 1 to 15 symbols of 0.14 s before each transmission, for a VOX that needs longer to key; Test plays exactly that leading noise at the output level, no call sign and nothing to decode, without a Stop button; the values have a fixed width, so the sliders never move); Keys (add, edit, Active, Retired or Compromised since when, an avatar per key: choose any picture; a still one opens the cropper, the picture fitted to the screen with a frame over it, the largest centred square first, the rest dimmed: dragging inside it (or beside it) moves it, dragging an edge or a corner (within 24 screen pixels, corner handles drawn inside) resizes it, its shape held between 2:1 and 1:2 by undoing what the dragged edge did, never moving the others, and at least 32 pixels of the picture a side; the arrow keys move it, with Shift they resize it; what it becomes is shown a moment after each change; Use halves the part until it has at most 256K pixels (one of fewer than 16K is drawn larger, up to them) and makes a WebP (or JPEG, as for attachments) of quality 0.8 down to 0.5 that fits 8 KiB, halving again while it doesn't and keeps 16K pixels (down to 0.3 at the last size), and the whole of a picture already within the limits goes as it is; an animation goes only as it is, any shape within the limits; see its size, format and airtime, send it as Fragments, all at once or one at a time, remove it; print revocations as hex, send a revocation by typing REVOKE, compromised over retired only, remove by typing DELETE; held keys count as trusted); Kept revocations (each with its key, reason, since when and when last sent; Send all packs them into as few frames as fit; on by default, every transmission but Hex fills its spare room with them, the one sent longest ago first; any sent revocation counts as sent, however it went out); Storage (persistence, usage and quota, budgets, export, import, last export); Appearance (System, Light, Dark, per device); About (the logo at full size up to 512 pixels, the whole 0BSD licence from LICENSE, its copyright and permission first, the file itself not linked as it has no extension and would download, the version, a fingerprint of the files the app runs from, worked out three seconds after start ("Version 67dbec43"), with how to match it to a commit, a link to the source code, and the disclaimer: delivery is never guaranteed, nothing is encrypted, the operator answers for their licence and local rules, no replacement for official emergency channels, then the licence's warranty disclaimer); Danger Zone (delete everything but the appearance by typing DELETE); then the Log.
- Safari grants persistent storage only to web apps added to the Home Screen or Dock and may otherwise delete stored data after 7 days without use, so the Station tab shows whether storage is persistent, suggests installing the app, and shows when the last export was made.
