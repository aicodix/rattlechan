# Rattlechan

A message board that travels as sound. The protocol is in SPEC.md (v0 draft, still changing).

## Rules

- No third-party libraries. Plain JavaScript (ES modules) plus the ROBUSTO, HYDRA and CRYPTO WebAssembly modules and the SCSU JavaScript module, copied in as they are.
- Never add encryption or anything that hides content. Signatures and MACs are fine.
- Little-endian everywhere.
- Tabs for indentation.
- SPEC.md is the source of truth: when code changes the protocol, update SPEC.md in the same commit.
- When something is unclear, ask instead of guessing. That includes gaps in SPEC.md: ask before deciding them in code.
- Every module gets a test file `<name>_test.mjs`, run with `node <name>_test.mjs`, no test framework.
- License: 0BSD.

## GUI

- Colors only through the variables in app.css, so every view works in light and dark, whether it follows the system or is forced.
- Never a flashing element. Nothing moves by itself: animated pictures and avatars show their first frame and play only while the mouse is over them or, on a touch screen, while a finger is on their message. Warnings latch for seconds instead of blinking. Under `prefers-reduced-motion` there are no transitions at all.

## Commit messages

Match the existing history:

- A short lowercase subject, no trailing period, under about 60 characters, saying what changed. Example: `moved block count computation out of encode function`.
- No body unless the reason is not obvious from the diff.
- No Co-Authored-By, Claude-Session or other trailers, and no links.
- Claude commits as `Claude <noreply@anthropic.com>`. Never use the maintainer's name or email.

## Next step

Done: records.js parses and encodes records (type classes, lengths, prefix chains and the ordering rule, Bundle, posts, value checks, the error table, post IDs, Keyed tags). records_test.mjs covers it with hand-built frames. crypto.js wraps crypto.wasm (copied from CRYPTO's docs/crypto.wasm at 2339005): keys, signing, the `verify` callback for the parser and revocations. crypto_test.mjs checks CRYPTO's known answers. hydra.js wraps hydra.wasm (copied from HYDRA's docs/hydra.wasm at 87fa55a): planning, encoding, `verifyBlock` for the parser, decoding, the relay check, and a Reassembler that collects blocks and makes Request-Root records. robusto.js wraps the four ROBUSTO modules (copied from aicodix/modem's robusto branch, docs/temp/ at 63eb078): `loadEncoder(rate)` picks modes and turns payloads and pings into audio, `loadDecoder(rate)` turns samples into events (sync, meta, ping, frame, error). scsu.js is SCSU's JavaScript module (copied from its module/scsu.js at c50f08c): `encode` and `decode`, used by the parser and by encodings.js, which builds encoders for GB 18030 and the Text-Table encodings from `TextDecoder` and picks the smallest text record with `smallestText(str)`. `TextDecoder` gets `ignoreBOM` for UTF-8 and UTF-16, so a U+FEFF stays text (only there: Node 22 drops a leading 0xFF in windows-1252 with it). Browsers (WHATWG) are the reference decoders; Node's ICU differs for IBM866, KOI8-U, windows-1255, Big5, Shift_JIS and EUC-KR and lacks ISO-8859-16, so encodings_test.html checks the encoders in the browser. wasm.js loads all modules. storage.js keeps the station's files on OPFS (or in memory for Node): precious/ and logged/ hold one file per frame named <kept>_<arrival>_<call sign>_<mode>.bin, each tier with its own byte budget (default 100 MiB) that evicts the oldest kept time first, so spam in the logged tier never evicts precious frames; touch() renews avatars, promote() and demote() move frames between tiers; the caller picks the tier (SPEC.md, Client policy); revocations/ forever, only for trusted keys; data/ and secrets/ as JSON. archive.js exports .tar.gz (tar.js, CompressionStream): data and secrets in separate archives; import only adds what is missing. Exported archives can pre-populate the GUI for testing.

The GUI is a PWA served from 127.0.0.1:8080 by `python3 -m http.server`, so modules load over fetch; `loadCrypto()`, `loadHydra()`, `loadEncoder(rate)` and `loadDecoder(rate)` without a source fetch their .wasm next to their .js. The page loads the ROBUSTO modules for `AudioContext.sampleRate` (44100 or 48000).

For the GUI: Safari grants persistent storage (`navigator.storage.persist()`) only to web apps added to the Home Screen or Dock; for an ordinary website it may delete everything a script stored after 7 days without use. So the GUI shows whether storage is persistent next to usage and quota, suggests installing the app when it isn't, and shows when the last export was made, since exports are the backup either way. The maintainer runs encodings_test.html and storage_test.html in Chrome and Safari; both passed there.

The GUI receives, and sends signed posts only (unsigned ones are for sensors and experiments outside the GUI): index.html with app.js, render.js and app.css, phone first, with tabs at the bottom (Log, Send and Station; Boards and Inbox come once there is something to put in them). sender.js composes topics, replies (from a Reply button on posts with an ID, so only signed or Keyed ones, as unsigned posts have none) and bare messages (not offered in the GUI), texts in their smallest encoding. A Topic goes to everyone by default, or under "To" to a call sign (To-Call), a key (To-Key, picked from the keys seen in the log, station.seen(), or pasted as hex), a name (To-Name) or a board (To-Group-Name), each with a hint on how reliable it is; this is how to contact someone the station never heard from, and the address resets after each sent post; compose() takes a sign function and puts the records inside one Signed record; a post carries the signing key's From-Call and From-Name inside it only when "Include …" under "Sign as" is ticked, which is off by default and again after each sent post, for an operator who hasn't posted in a long time (Replies take From prefixes, never To prefixes, so a key that only replies can still say who it is). keys.js keeps several keys in secrets/keys.json, each with a label, From-Call, From-Name and both revocations signed when it arrives (generated, imported as 64 hex characters, or from a secrets archive); the Send tab picks one under "Sign as" and stays disabled without keys. Held keys count as trusted (trustOwn() adds them to the trust list at startup and after imports; removing a key, which takes typing DELETE, leaves the trust list alone), and their posts say "your key" instead of a trust button and show the call sign and name from the key list. "Print revocations" opens a window with both revocations as hex, one page each, with the note for whoever finds them; QR codes come next. The station settings keep only the preamble's call sign. Frames only use modes whose SNR threshold (the modem README's thresholds, SNR = -awgn level, in THRESHOLDS) is at most the setting (default 10 dB) within the seconds per frame (default 5); a post that doesn't fit offers one longer frame (the fewest seconds up to 60 that carry it) or Fragments at the current seconds with 25% extra blocks (at least one, at most N). chain() puts all frames back to back in one transmission, every one but the first without its leading noise symbol, which only opens VOX and squelches. transmitter.js plays it out of the default output; receiving ignores the decoder's reports while sending and 1.5 s after, but keeps the microphone and decoder running (restarting the microphone is slow, Safari takes seconds) and the level meter moving. Sent frames are stored precious and remembered as the station's own by their BLAKE2s hash in data/own.json. receiver.js runs microphone -> capture_worklet.js -> decoder_worker.js (ROBUSTO off the main thread) and decodes recordings the same way; station.js parses, checks signatures, reassembles Fragments, stores (malformed frames, a bad signature included, are shown but never stored) and replays the store at startup. It keeps the trust list in data/trust.json, learns each key's call sign, name and newest avatar from its verified signed posts and Avatars, puts frames with a post or Avatar under a trusted key's verified signature (or reassembling to one) in the precious tier and the rest in the logged tier, moves frames when trust changes, and renews a key's avatar frame with touch() on each new post. render.js draws an identicon (mirrored 5x5 grid, colours --id-0..7) beside every verified signature, or the avatar with call sign and name once the key is trusted; Trust asks first, showing the whole fingerprint, Untrust is one tap; From prefixes are marked unverified unless signed by a trusted key; pictures are drawn right away under a trusted key's signature and otherwise only when asked for. The transmitter is keyed by VOX only. sw.js caches network first, so it works offline once opened. Colors follow the browser (prefers-color-scheme) unless Station, Appearance picks Light or Dark, kept per device in localStorage. The Station tab ends in a Danger Zone that deletes everything (store.clear(), the offline cache and what the page remembers, except the appearance) once DELETE is typed.
